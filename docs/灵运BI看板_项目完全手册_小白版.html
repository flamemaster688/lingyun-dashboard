一、一句话看懂这个项目

它是一个 纯前端 的数据看板网站：没有后端服务器、没有数据库。所有图表需要的数据，都提前准备好打包进网页里；你打开网页，浏览器自己解密、自己画图。好处是部署简单、能直接发公开链接；代价是“换数据”要在电脑上跑脚本重新生成。

安全设计：数据文件 data.js.enc 用 AES-256-GCM 加密，打开看板要先输密码 12345678 才能解密。即使文件被下载，看到的也是密文。

二、前后端架构与框架

前端（网页）= HTML + CSS + 原生 JavaScript，图表用 ECharts 库。这就是全部，没有用 React/Vue 这类框架（目前）。
后端 = 没有。你会在项目里看到一些 Python 文件（app.py、build/*.py），它们不是网站后台，而是「数据准备工具」：只在换数据时本地跑一次。
数据库 = 没有。数据就放在一个 JS 文件（加密前是 data.js，加密后是 data.js.enc）里。

图1：整体架构。① 浏览器里跑前端+解密；② 构建端本地用 Excel 生成数据；③ 部署到静态托管。全程无后端、无数据库。

四、数据从哪来 / 什么是“数据接口”

看板里所有页面都通过内核提供的统一取数接口 window.LY.data(...) 拿数据，页面自己不直连任何外部表格。数据从“构建端”准备好后，随网页一起发给浏览器。

“数据接口”小白理解：就是网页和内核之间约定好的“取数窗口”。页面说“我要总览数据”，内核从 window.LINGYUN_DATA 里取出对应那块给它。这个“窗口”在前端内部，不是网络接口。

七、从 git 拉取后，改什么 / 改哪些文件

路径 A：只是想更新看板数据

  1. 把最新的 4 份 Excel 放进 build/sources/（或确认已有）。
  2. 赵莹跑：python build/build_from_xlsx.py → extract → merge → build_extra.py → encrypt_data.js(密码) → bundle.js。
  3. 部署（CloudStudio / GitHub Pages）。

路径 B：想改看板样式/某张图

  1. 改对应的 pages/<id>.js（图表逻辑）或 style.v6.css（配色排版）。
  2. 本地用 app.py 起个本地预览（开发用，非上线）。
  3. 改完打包+部署。
铁律：不要手动改 data.js / data.js.enc（由脚本生成）；不要改 core/（除非你懂内核）；换数据一定走脚本。

九、改成 Vue 架构怎么落地

当前是“原生 JS + 全局 window.LY 内核”。要升级到 Vue（组件化、更易维护），建议分步：

  1. 保持数据层不动：data.js.enc + decrypt.js + LY.data 接口原样保留，这是与后端的“契约”，先别动。
  2. 引入 Vue 3 + Vite：新建 web/ 目录，用 Vite 构建；把每个 pages/<id>.js 改写成 .vue 单文件组件。
  3. 适配取数：在 Vue 里用 import { LY } from '@/core' 或 composable 封装 LY.data，页面改为组合式 API 调用。
  4. 图表：ECharts 继续用（Vue 有现成封装），把原来的图表配置搬进组件。
  5. 路由：用 Vue Router 替换现在的 tab 手写切换。
  6. 渐进迁移：先迁 1~2 个页面验证，再逐步替换，期间两套并存。
升级后目录示意：web/src/views/<页面>.vue · web/src/composables/useLingyun.js · web/src/router；数据仍走 build/ 生成、dist/ 部署。
